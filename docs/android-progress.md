# AirZelo for Android: progress and resume guide

Status: **work in progress. No APK has been built yet, and no Android tests exist yet.**
Branch: `feature/android-offline-app`, created from `feature/ios-offline-app` so it can reuse the shared
parity and schema tools in `ios/tools/`. Merging this branch would also bring in the iPhone work.
Nothing has been merged into `main`, released or hosted.

## Goal (from the owner's request)

A native, offline-first Android app (Kotlin + Jetpack Compose), installable as an APK, with the desktop's
business rules, tested for parity with the desktop app.

- **Screens:** dashboard, customers, suppliers, bookings (passengers, flights, PNR), payments, expenses,
  refunds, invoices, reports, cashbook, backup/restore, settings.
- **Security:** passport numbers encrypted with an Android Keystore key, encrypted backups, device
  authentication, and no sensitive data in logs.
- **PDFs:** tickets, invoices, receipts and credit notes, made on the device.
- **CI:** builds a release APK, runs real tests (parity, money, backup/restore), and uploads the APK.
- **No cloud:** no cloud sync and no remote database.

## Architecture (decided)

- `android/engine`: **pure Kotlin/JVM**, holding all business logic. It is a line-by-line port of the iPhone engine
  `ios/AirZeloKit/Sources/AirZeloKit`, which itself passes desktop parity.
  - It runs on any SQLite through the `SqlDb` interface (`Db.kt`): Android's `SQLiteDatabase` in the app, and
    xerial sqlite-jdbc in the JVM tests (a test dependency).
  - Money is `BigDecimal` with `HALF_UP`, which is the same as Python's `Decimal` with `ROUND_HALF_UP`. Amounts are
    integer paise in `Long`.
  - The schema is the desktop v4 schema, read from
    `engine/src/main/resources/com/airzelo/engine/schema.json`. That file is generated by
    `python3 ios/tools/export_schema.py`, and `--check` verifies both the iOS and the Android output.
- `android/app`: the Android app with Compose, BiometricPrompt, Keystore, SAF import/export and FLAG_SECURE.
  `settings.gradle.kts` includes `:app` unless `AZ_ENGINE_ONLY=1` is set, so the engine builds without an Android SDK.
- **Toolchain:** Gradle 8.10.2 (wrapper committed), Kotlin 2.0.21, AGP 8.7.3, JDK 17.

   - return the last insert id;

3. **Engine tests**: port `ios/AirZeloKit/Sources/AirZeloCheckSuite/*.swift` to JUnit, one test per check.
   - **Parity:** needs `AZ_PARITY_DIR`; it must fail, not skip, when `AZ_REQUIRE_PARITY=1`.
   - **Money vectors**, the **worked example**, immutability, idempotency, edit round-trip, sealed passport.
   - **Security:** tamper.
   - **Backups:** backup round trip, desktop import, export for desktop, corruption recovery, scale.
4. **`Backup.kt`**: port `Backup/BackupCrypto.swift` and `AgencyStore.swift`.
   - Use `java.util.zip` for the zip format.
   - Keep the AZBK1 container format identical: AES-GCM chunks, HKDF-SHA256 for the device key, PBKDF2-SHA256 at
     600,000 iterations for passphrases. Then exports are compatible with the iPhone app.
5. **PDF**: a pure-Kotlin PDF writer, ported from the desktop's standard-library `core/server/pdfkit.py` (Helvetica
   widths are in that file). It needs tickets (layout as `core/server/ticket.py`), invoices / credit notes (as iOS
   `PDF/InvoicePDF.swift`) and a payment receipt. Test with PDFBox text extraction (a test dependency).
6. **`android/app`**:
   - `AndroidSqlDb` implementing `SqlDb`, and a Keystore `KeyProvider` (AES/GCM key, `setUserAuthenticationRequired` off;
     the app gates with BiometricPrompt + DEVICE_CREDENTIAL);
   - FLAG_SECURE, and Compose screens for every item on the list above;
   - SAF backup import / export, and PDF sharing via FileProvider.
7. **Workflow test** (Robolectric + Compose UI test): create a booking with a passenger, record a payment, see
   Unpaid change to Paid, edit without losing fields, export and restore a backup.
8. **CI** `.github/workflows/android.yml` (ubuntu-latest, JDK 17):
   - `python3 ios/tools/export_schema.py --check`, then the parity fixtures:
     `python3 ios/tools/parity.py --out $RUNNER_TEMP/parity --seed 7 --ops 600`;
   - `AZ_PARITY_DIR=... AZ_REQUIRE_PARITY=1 ./gradlew :engine:test :app:testReleaseUnitTest :app:assembleRelease`;
   - `python3 ios/tools/parity.py --check-export <dir>` on the engine's export;
   - upload the APK artifact.
9. **APK signing**:
   - Without secrets, sign with a throwaway key, and **name the APK so that is clear**. It installs, but can't be updated in place.
   - With the owner's approval, create a permanent release keystore and store it as repository secrets
     (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`).
   - Never commit a keystore (`*.jks` and `*.keystore` are git-ignored).

## Resume

Needs JDK 17. On the owner's Mac, Java is not installed; the previous session used a scratchpad JDK. Install Temurin 17, or let CI build.
```bash
git fetch origin && git checkout feature/android-offline-app
python3 ios/tools/export_schema.py --check
python3 ios/tools/parity.py --out /tmp/parity --seed 7 --ops 600
cd android && AZ_ENGINE_ONLY=1 ./gradlew :engine:compileKotlin
cd android && AZ_ENGINE_ONLY=1 AZ_PARITY_DIR=/tmp/parity AZ_REQUIRE_PARITY=1 ./gradlew :engine:test
```
A full build with the app needs the Android SDK (`ANDROID_HOME`). The GitHub `ubuntu-latest` runners have it.

## Conventions to keep

- Every service takes `Fields` (`Map<String, JValue>`) exactly like the desktop JSON API. Use `data.arg("key")` (not `data.get`).
- Never log payloads: they can contain passport numbers. The audit log stores passports only sealed or as "(encrypted)".
- A sealed value that can't be decrypted on this device is kept as is (`FieldCrypto.open` returns it unchanged).
- Re-saving a booking must start from `bookingEditFields(id)`, so no stored field or manual tax is lost.
